# Global Elections Calendar 2.0.0: release notes

Version 2.0.0 replaces the 7-source calendar with a month-by-month view of 10 monitoring
sources, with data health checks, honest date labels and a list of items to review.
The extension's permissions are unchanged from v1.0.2 (`storage`, `alarms`, and the one raw-data host).

## What is new

- **Banner and health panel.** One banner shows the worst condition (data more than 36 hours old,
  a failed update, source errors, warnings, acknowledged issues) with counts. Click it for each
  source's reasons. The footer says when the data was generated and last checked.
- **Honest date labels.** Month-only dates read "October — day unconfirmed", expected periods read
  "Expected between 2 Nov and 31 Jan", disagreements read "Possibly postponed — sources
  disagree" or "Sources disagree on date". Saved copies of a source say "Using source data from
  <date>" and, after seven days, "Unverified since <date>".
- **Tabs.** Upcoming, Past (formerly Results) and All. The tab shown always matches the list.
- **Months.** A month shows every election whose dates overlap it. The data covers five months:
  the previous month, the current month and the next three.
- **Needs attention and undated.** A collapsed section above the list holds items the calendar
  could not place. Filters never hide them; the search box narrows them.
- **Pins by place.** Pins refer to places rather than to spelled names. A pinned country also
  shows the places that belong to it (for example Georgia also shows Abkhazia and South
  Ossetia), and the options page says "Also shows: ..." for such rows.

## Updating

### Loaded unpacked ("Load unpacked")

1. In `chrome://extensions`, note the folder the extension was loaded from.
2. Delete the folder's contents (keep the folder).
3. Extract the v2.0.0 ZIP into it.
4. Click Reload on the extension's card.

Do not remove the extension: removing it deletes your pins and settings. The extension ID depends
on the folder path, and the manifest carries no `key`.

### Chrome Web Store

Upload the same ZIP. Users update automatically, with the same ID and the same storage.
**No permission prompt is expected**, because the permissions are v1.0.2's. That is an expectation:
it is confirmed only once a Store update lands (open item O4).

## Pins from v1.0.2

- **Migration, once.** On the first run after the update, the worker maps each name in the v1
  `pinned_countries` list to a place and saves the result. A pin deleted afterwards stays deleted.
  Pins changed in v1.0.2 after the migration (for example after a rollback to v1.0.2 and a second
  upgrade) are not migrated again.
- **Minority aliases.** Six places had two spellings in the v1.0.2 feed history. v2.0.0 shows the
  majority spelling (the display name) and keeps the other as an alias. A v1.0.2 pin on an alias
  is migrated onto the place and appears under the display name. Check these six after the
  update:

  | Place | Display name | Minority alias |
  |---|---|---|
  | Cape Verde | Cape Verde | Cabo Verde |
  | North Korea | North Korea | Democratic People's Republic of Korea |
  | Laos | Laos | Lao People's Democratic Republic |
  | Vietnam | Vietnam | Viet Nam |
  | Philippines | Philippines | The Philippines |
  | Sao Tome and Principe | Sao Tome and Principe | São Tomé e Príncipe |

  Names that match no place are kept as "unresolved pins" on the options page, with a Remove
  button. They filter nothing.
- **Options page (D4).** The dead "selected countries" controls are gone: there are no checkboxes
  and no "Select All", "Clear All" or "Save" buttons. Pins save at once. The stored
  `selected_countries` value is left as it was.
- **Help (D7).** `help.html` opens once, when the extension is installed, and from the popup's
  Help button.

## Differences from v1.0.2 worth knowing

- v1.0.2 counted cards, not elections, and showed a month-only date as "1 OCT". v2.0.0 counts
  election records and shows "October — day unconfirmed".
- Users still on v1.0.1 read a data URL that no longer serves the feed. They must update.

## Evidence limits

- Chrome's Reload button is not driven by any test (R49). The update steps above follow the
  design (§12.8), and the first real Reload is the release check.
- "No permission prompt" on a Web Store update is expected and not yet observed (O4).
- The real action popup at 200 % zoom is checked by hand before release (R63); the automated
  checks use a 380 x 300 viewport as a stand-in.
- The ZIP's bytes are reproducible for one Python minor version and one zlib version. The
  `RELEASES.md` row names both.
